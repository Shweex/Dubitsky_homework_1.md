# Домашнє завдання 1. Основи комп'ютерних мереж

Команди виконано в терміналі Linux (WSL2) на цьому комп’ютері.

---

## Завдання 1. Дослідження мережі

Команда:

```bash
ip a
```

Результат:

```text
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
    inet 10.255.255.254/32 brd 10.255.255.254 scope global lo
       valid_lft forever preferred_lft forever
    inet6 ::1/128 scope host proto kernel_lo
       valid_lft forever preferred_lft forever
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    link/ether 00:15:5d:04:19:53 brd ff:ff:ff:ff:ff:ff
    altname enx00155d041953
    inet 172.28.55.251/20 brd 172.28.63.255 scope global eth0
       valid_lft forever preferred_lft forever
    inet6 fe80::215:5dff:fe04:1953/64 scope link proto kernel_ll
       valid_lft forever preferred_lft forever
```

Робочий інтерфейс для виходу в мережу — **eth0**. Інтерфейс **lo** є петлею (loopback): адреса `127.0.0.1` обслуговує лише цей самий комп’ютер. Адреса `10.255.255.254/32` на `lo` — службова адреса DNS у WSL, тому її не беру як адресу підключення.

Параметри інтерфейсу **eth0**:

- **Інтерфейс:** `eth0` (альтернативне ім’я `enx00155d041953`)
- **Тип підключення:** Ethernet. Це віртуальний адаптер WSL2 на шині Hyper-V VMBus, стан інтерфейсу `UP`. Сам комп’ютер у домашню мережу виходить через Wi-Fi, а Linux у WSL бачить свій канал як Ethernet.
- **MAC-адреса:** `00:15:5d:04:19:53` (канальний рівень моделі OSI, рівень 2)
- **IP-адреса:** `172.28.55.251` — мережевий рівень моделі OSI (рівень 3, Network). На цьому рівні працює логічна адресація вузлів.
- **Маска:** `255.255.240.0`, префікс `/20` — теж мережевий рівень моделі OSI (рівень 3, Network). Маска відділяє мережеву частину адреси від частини хоста.
- **Gateway:** `172.28.48.1`
- **Broadcast:** `172.28.63.255`
- **Hosts:** `4094`

Розрахунок кількості хостів:

- Довжина префікса `/20`, під номер хоста лишається `32 − 20 = 12` біт.
- Усього адрес у підмережі: `2^12 = 4096`.
- Дві адреси службові: адреса мережі `172.28.48.0` і широкомовна адреса `172.28.63.255`.
- Придатних адрес хостів: `4096 − 2 = 4094`.
- Діапазон адрес хостів: `172.28.48.1` — `172.28.63.254`.

Шлюз `172.28.48.1` взято з маршруту за замовчуванням (команда завдання 2). У виводі `ip a` є адреса інтерфейсу, довжина префікса і broadcast (`brd 172.28.63.255`).

## Завдання 2. Дослідження маршрутизації

Команда:

```bash
ip r
```

Результат:

```text
default via 172.28.48.1 dev eth0 proto kernel
172.28.48.0/20 dev eth0 proto kernel scope link src 172.28.55.251
```

**Протокол, через який у таблиці позначено отримання маршруту: `kernel`.**

Обидва записи мають поле `proto kernel`. Так ядро Linux позначає маршрути, які воно додало разом із адресою інтерфейсу `eth0`.

- `172.28.48.0/20 dev eth0 proto kernel scope link src 172.28.55.251` — підключений маршрут своєї підмережі. Пакети до адрес `172.28.48.0–172.28.63.255` ядро відправляє прямо через `eth0`, джерело — `172.28.55.251`.
- `default via 172.28.48.1 dev eth0 proto kernel` — маршрут за замовчуванням. Решта трафіку йде на шлюз `172.28.48.1`.

WSL2 сам призначає адресу віртуальному інтерфейсу, тому в таблиці джерело маршруту — ядро. Окремого значення `proto dhcp` у цьому виводі немає.

Адреса комп’ютера в домашній мережі Wi-Fi інша: `192.168.1.147/24`. Її Windows отримала протоколом **DHCP** від домашнього роутера, шлюз цієї мережі — `192.168.1.1`. Цю адресу показує конфігурація адаптера Windows, а таблиця `ip r` у WSL описує вже внутрішню мережу віртуального адаптера.

## Завдання 3. Знаходження публічної IP-адреси

Команда:

```bash
curl ifconfig.io
```

Результат:

```text
77.241.136.87
```

Порівняння адрес:

- Локальна адреса Linux (WSL2, `eth0`): `172.28.55.251`
- Адреса комп’ютера в домашній мережі Wi-Fi: `192.168.1.147`
- Публічна адреса: `77.241.136.87`

**Чи однакові вони?** Ні. Локальні адреси і публічна адреса різні.

**Чому так.** `172.28.55.251` і `192.168.1.147` належать до приватних діапазонів (RFC 1918). Такі адреси діють лише всередині локальної мережі, і маршрутизатори Інтернету їх не просувають. `77.241.136.87` — публічна адреса, її видно ззовні.

Між терміналом Linux і Інтернетом адреса змінюється двічі, обидва рази через NAT (підміну адрес):

1. Віртуальний комутатор WSL. Гостьова система має адресу `172.28.55.251`, а її шлюз `172.28.48.1` — це віртуальний адаптер Windows. Хост підміняє адресу гостя на свою адресу в домашній мережі.
2. Домашній роутер. У Wi-Fi комп’ютер має адресу `192.168.1.147`, шлюз `192.168.1.1` — це роутер. Роутер виконує NAT для всієї квартирної мережі: кілька пристроїв виходять в Інтернет з однієї публічної адреси, яку провайдер видав зовнішньому інтерфейсу роутера.

Тому `curl ifconfig.io` повертає `77.241.136.87`. Сервіс бачить адресу, з якої домашній роутер виходить в Інтернет, а не приватну адресу WSL і не адресу комп’ютера в мережі `192.168.1.0/24`. Саме в цьому роль домашнього роутера: він відділяє приватну мережу від Інтернету і підміняє внутрішні адреси однією публічною.
